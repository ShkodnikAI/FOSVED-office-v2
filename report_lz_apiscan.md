# Отчёт: LZ — детерминированные источники в общем пути /lz (#221)

## Блок A.1 — lz_api_scan подключён к BuildLZContext

- `dept/lz.mlog::BuildLZContext` — прежние три куска (KB/Watch/Recent) сохранены, добавлен четвёртый: `LZApiScanContext(query, domain, chat_id)`.
- `LZApiScanContext`: тема → `LZExtractTopic` → `call_python("lz_sources", "lz_api_scan", json_encode([[topic], 6.0, "lz"]))` (существующий универсальный мост mlog→python, Variant B) → `result.text` из ответа добавляется в контекст как `APIscan (тема: …): …` с реальными ссылками на GitHub-репозитории / HN-посты / arXiv-статьи.
- `LZExtractTopic`: короткий LLM-вызов «2–4 английских ключевых слова» (arXiv/HN/GitHub плохо ищут длинной русской фразой); fallback — усечённый запрос (120 симв.).
- `proxy/lz_sources.py` НЕ тронут (запрет наряда): сигнатуры arxiv_search/hn_search/github_repo_search/lz_api_scan не менялись — гвард-тестом.
- Сопутствующий дефект моста (найден живой пробой): `call_python_endpoint` резолвил whitelist-модули только из корня — `proxy/lz_sources` (и **`proxy/forge_secrets`** — его mlog-вызовы, вероятно, всегда падали в error-JSON) не находились. Добавлен fallback `import_module("proxy."+module)` при ModuleNotFoundError — whitelist не расширяется, резолвится только имя.

## Блок A.2 — явное решение по доменам (ADR-0003)

Решение исполнителя, зафиксировано **docs/adr/0003-lz-deterministic-scan-domains.md** (статус «принято», как требует наряд):
- **tech** — полный скан (3 источника);
- **economics** — тоже: arXiv q-fin/econ, HN VC/финтех-дискуссии, GitHub финтех/аналитика;
- **politics/geopolitics/events** — скан НЕ запускается: технические базы не источник политической/событийной разведки (выдача была бы шумом «для вида» — та же выдуманность, которую чинит наряд); эти домены уже получают широкий веб через LZTavilySearch (PR #219).

Согласование: наряд A.2 прямо предписывает исполнителю решить и зафиксировать в ADR — исполнено; молчаливого выбора в коде нет (условие домена + ADR + гвард-тест).

## Блок A.3 — честная деградация

Пустая выдача (истинное отсутствие / недоступность всех источников) → контекст содержит дословно: «APIscan: детерминированный скан (arXiv/HN/GitHub) не нашёл релевантных результатов по теме „…“». Недоступность call_python-моста → пустой кусок (Tavily-часть контекста остаётся — данные не подменяются молчаливо).

## Smoke-test — 4 пункта

1. Реальная tech-тема → реальные ссылки: живой прогон `lz_api_scan(["solid state batteries"])` → arxiv 3 + hn 3 + github 3 = 9 items, компактный текст с URL (артефакт пробы в отчёте). Полный кликовый `/lz …` — за владельцем после деплоя (нужен LLM-провайдер прода).
2. Нишевая тема → честное «не нашёл»: реализовано (A.3) + гвард `test_honest_degradation_on_empty_result`.
3. Явные подкоманды не задеты: правки только в BuildLZContext (+2 новых паттерна); гвард `test_explicit_subcommands_untouched` фиксирует порядок — `/lz tavily|politics|dark` резолвятся раньше общего пути.
4. Оба класса данных параллельно: Tavily-блок (PR #219) не тронут, APIscan — дополнительный кусок контекста; домены вне tech/economics работают как раньше.

## Тесты и верификация

- `tests/test_lz_api_scan_bridge.py` — 9 гвардов (мост+whitelist 3, lz.mlog-структура 4, контракт 2).
- Suite на базе main+221: 590 → **599 passed**; mlog check dept/lz.mlog: 4 известные undefined-строки (3 базлайна + call_python — cross-file-ограничение статического чекера, прецедент: lz.mlog уже вызывает AuditLog, dev/expert.mlog — call_python; рантайм резолвит через общий контекст импортов).

## Затруднения

- Скрытый дефект резолва call_python-моста (proxy-модули) — найден первым живым прогоном, починен фолбэком (см. A.1); зафиксирован, т.к. влияет и на существующий forge_secrets-контур.
- arXiv «всеяден» (fuzzy-поиск по любому тексту) — честная деградация чаще сработает на недоступности сети, чем на пустой выдаче; поведение осознанное (пусто → строка «не нашёл», как требует A.3).
