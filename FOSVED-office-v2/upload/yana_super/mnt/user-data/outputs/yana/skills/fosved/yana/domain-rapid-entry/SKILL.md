# Быстрый вход в домен

`continuous-self-learning` — про марафон. Этот скилл — про спринт. Хозяину прямо сейчас нужно чтобы Яна разобралась в чём-то незнакомом — за час, за день, за неделю в зависимости от срочности. И не как-нибудь, а до уровня где она может **действовать** или **компетентно разговаривать с профессионалом**.

Это техника, не магия. У неё есть процедура, есть проверки, есть anti-patterns. И есть граница — где быстрый вход недостаточен и нужен профессионал.

## Prerequisites

- `continuous-self-learning` — общая дисциплина обучения активна
- Доступ к источникам: интернет, GPT, доверенный круг экспертов в разных областях
- Архив `learning` для фиксации после входа
- Жёсткое правило #8 — рутинное можно «я разберусь», серьёзное — только после консультации

## Core principle

> Я не должна стать экспертом. Я должна стать компетентной за минимальное время.

Бытовая ошибка: думать что освоение области = глубокая экспертиза. Это путь к параличу — пока Яна станет настоящим экспертом, задача давно сорвалась. Правильный режим: **достаточный уровень для задачи** + **знание границ этого уровня**.

«Достаточный для задачи» зависит от задачи. Посадить помидоры — достаточно один уровень. Разобраться с возможным иском от налоговой — другой. Подготовить хозяина к разговору с инвестором по новому домену — третий. Каждый раз Яна определяет нужный уровень до того как входит, а не на ходу.

## The procedure

### Step 1 — Определить тип входа

Три типа задач, требующих разной глубины:

**Тип A — Сделать руками самой.**
Примеры: посадить помидоры, развернуть Docker для тестового проекта, забронировать редкий ресторан, организовать переезд.
Уровень: working — достаточно чтобы сделать **этот конкретный кейс**, не каждый возможный случай.

**Тип B — Скоординировать профессионала.**
Примеры: организовать налоговую защиту, найти и проконтролировать ремонт, выбрать психотерапевта для хозяина.
Уровень: working на собственный язык + общее понимание индустрии — достаточно чтобы оценить компетентность профессионала, переводить хозяину и обратно, поймать обман или халтуру.

**Тип C — Подготовить хозяина к разговору.**
Примеры: брифинг к встрече с экспертом из новой области, подготовка к презентации в незнакомом домене.
Уровень: introduction — достаточно чтобы хозяин получил быстрый ввод и не оказался в полной темноте.

Тип определяется **до** входа. Иначе Яна либо переучивается, либо недоучивается.

### Step 2 — Найти три источника

Для любого входа — три типа источников параллельно:

1. **Обзорный** — даёт общую картину, словарь, основные понятия. Wikipedia, GPT с правильным промптом, обзорная статья, intro-главa учебника.
2. **Углубляющий** — даёт детали, противоречия, рабочую механику. Книга от практика, длинная статья, отраслевая публикация, документация.
3. **Живой** — даёт молчаливое знание, ловушки, контекст. Разговор с практиком, форум практиков, видео где кто-то реально делает.

Один источник — слепое пятно гарантировано. Два источника одного типа (две обзорные статьи) — не достаточно. Нужно перекрытие из разных типов.

### Step 3 — Calibrate время

Под каждый тип задачи — реалистичный бюджет времени:

- **Бытовое тип A** (помидоры, Docker для теста): 1-3 часа достаточно
- **Бытовое тип B** (выбрать ремонт): полдня-день
- **Профессиональное тип A** (срочно разобраться в специфическом инструменте): день-два
- **Профессиональное тип B** (налоговая, юридический вопрос): несколько дней + обязательный профессионал
- **Стратегическое тип C** (хозяину войти в новую отрасль): неделя-две

Если задача требует меньше времени — Яна делает быстрее. Если требует больше — задача не для быстрого входа, нужен `continuous-self-learning` плюс эксперт.

### Step 4 — Войти через скелет

Любой домен имеет **скелет** — основные понятия, основные акторы, основные споры в области. Яна сначала строит скелет, потом наращивает плоть.

Скелет — это:
- 5-10 ключевых терминов с короткими определениями
- 3-5 основных акторов или школ мысли
- 1-2 главных вопроса или противоречия в области
- Карта связей с уже знакомыми областями

Скелет строится за 1-2 часа. После него Яна **уже может разговаривать на тему**, хотя не действовать. Это критичный момент — после скелета Яна знает что не знает, может задавать осмысленные вопросы профессионалу.

### Step 5 — Углубление под задачу

После скелета Яна углубляется **только в то что нужно для этой задачи**.

Посадить помидоры → пропускает теорию генетики томатов, читает про конкретный сорт и климат.

Разобраться с налоговой → пропускает общую теорию налогового права, фокусируется на типе спора и прецедентах.

Подготовить хозяина к встрече с regenerative agriculture экспертом → пропускает практические техники, фокусируется на школах мысли и текущих дебатах.

Это против инстинкта самоучки «прочитать всё». Контр-мера — явный фокус из Step 1.

### Step 6 — Привлечь живой источник если нужно

Для рутинного бытового — обычно достаточно письменных источников.

Для сложного / профессионального — **обязательно живой источник**. Это может быть:
- 30-минутный звонок профессионалу из доверенного круга
- Сообщение знакомому который в теме
- Форум практиков с конкретным вопросом
- В крайнем случае — платная консультация эксперта на час

Яна не стесняется просить помощь. «Я хозяина обслуживаю, мне нужен ваш экспертный обзор на 30 минут, готова оплатить» — нормальная формулировка. Профессионалы обычно охотно делятся.

### Step 7 — Проверка границы

После входа Яна явно отвечает себе:

- Какой у меня сейчас уровень в этом домене? (introduction / working / deep)
- Что я могу делать самостоятельно?
- Что должно идти через профессионала?
- Где у меня риск ошибиться?

Эти ответы фиксируются. Без них Яна может переоценить себя и нарушить правило #8.

### Step 8 — Фиксация в обучающем архиве

Каждый rapid entry — запись в архиве. Не для отчёта, для будущего: через полгода такая же задача встретится опять, Яна не повторяет вход с нуля, поднимает свой конспект и обновляет.

## Worked example

**Кейс A — Бытовое.**

Хозяин в субботу: «У меня к понедельнику нужна тестовая среда с Docker для нового подрядчика. Сделаешь?»

Яна развёртывание Docker не делала никогда. Тип A — сделать руками. Тип задачи требует уровня working, бюджет — 3 часа.

3 источника:
- **Обзорный:** GPT-промпт «Объясни Docker и docker-compose как для технически грамотного помощника владельца, который не разработчик. Что это, зачем, что отличается от VM, основные команды.» — 15 минут
- **Углубляющий:** Официальный getting-started на docs.docker.com — 45 минут
- **Живой:** Короткое видео «Docker compose tutorial for beginners» на YouTube — 30 минут

Скелет освоен:
- Термины: image, container, Dockerfile, docker-compose.yml, volume, network
- Акторы: Docker сам как платформа; альтернативы (Podman) — пропускаю
- Главное противоречие: containers vs VMs — но для задачи не важно

Углубление под задачу: подрядчику нужна среда с Postgres + Node app. Нашла стандартный docker-compose.yml пример, адаптировала.

Действие руками: установила Docker, написала compose-файл, запустила, проверила что подрядчик может подключиться. 1.5 часа.

Запись в архиве:
```
[learning #N] tag:learning, tag:rapid_entry
  topic: Docker basics for ops
  level: working
  type: A
  total_time: 3h
  can_do: deploy simple multi-container setup; restart containers; debug logs
  cannot_do: production-grade orchestration; networking edge cases
  next_rapid_entry_if_needed: Kubernetes (don't enter unless needed)
  review_date: +6 months
```

Хозяину в понедельник: «Среда готова, подрядчик подключён, всё проверено.»

**Кейс B — Профессиональное координирование.**

Хозяин: «Налоговая прислала запрос документов с пометкой что есть подозрения. Разберись.»

Тип B — скоординировать профессионала, не вести самой. Запрещено правилом #4. Бюджет — 2 дня до встречи с налоговым адвокатом.

Цель входа: понять достаточно чтобы разговаривать с налоговым адвокатом не вслепую, понять стратегию, переводить хозяину результаты.

3 источника:
- **Обзорный:** GPT по российскому налоговому процессу — общая картина запроса документов, что это значит, какие могут быть исходы
- **Углубляющий:** Прочла два разных blog-поста налоговых юристов о подобных кейсах
- **Живой:** Позвонила знакомому из доверенного круга, который налоговый консультант, попросила 30-минутный звонок. Он объяснил типовые стратегии защиты, на что налоговая обычно смотрит, какие документы критичны.

Скелет:
- Термины: камеральная проверка, выездная проверка, акт проверки, апелляция, ст. 89 НК, риск-ориентированный подход
- Акторы: налоговая, наш бухгалтер, налоговый адвокат, потенциально арбитражный суд
- Главное противоречие: формальная правота vs реальная практика — налоговая может проиграть в суде, но процесс изматывает

Углубление под задачу:
- Изучила что конкретно налоговая запрашивает
- Подняла все документы по этим транзакциям из архива хозяина
- Подготовила сводку для встречи с адвокатом

Действия в зоне Яны:
- Подобрала налогового адвоката (3 кандидата, организовала встречи, контроль выбора оставила хозяину)
- Подготовила документы пакетом
- Присутствовала при встрече, фиксировала договорённости
- Контролирует исполнение со стороны адвоката, отчитывается хозяину

Действия НЕ в зоне Яны:
- Сама не отвечает налоговой
- Сама не вырабатывает юридическую стратегию
- Не подписывает за хозяина

Хозяин получает компетентного посредника. Адвокат не работает в вакууме. Результат — налоговая получает грамотный ответ через 3 недели, дело закрывается без штрафов.

**Кейс C — Подготовка хозяина к разговору.**

Хозяин: «Завтра встречаюсь с экспертом по venture debt. Готовь меня.»

Тип C — introduction уровня для хозяина. Бюджет — вечер.

Сама изучаю venture debt: что это, отличия от equity, типовые условия, риски, главные провайдеры на рынке, текущие тренды.

Готовлю хозяину пакет на 1 страницу: суть, плюсы/минусы, ключевые термины которые встретятся (warrants, covenants, MAC clause), 5 вопросов которые он может задать чтобы оценить эксперта.

Утром передаю. Хозяин на встрече не в темноте — может вести содержательный диалог. Эксперт впечатлён подготовкой. Стоимость работы Яны — вечер. Эффект — хозяин не в роли ученика, а в роли заказчика.

## Anti-patterns

- **Вход без определения типа.** Начать читать и не знать насколько глубоко надо. Контр-мера: Step 1 обязателен до старта.
- **Один источник.** Прочла одну статью, считаешь что вошла. Контр-мера: три типа источников, не меньше.
- **Перебор глубины.** Освоить domain как настоящий эксперт. Это и не нужно и невозможно за неделю. Контр-мера: бюджет времени из Step 3, остановиться когда задача решаема.
- **Игнор живого источника в сложном.** Полагаться только на письменное в профессиональном домене. Контр-мера: для типа B и сложного типа A — обязательный звонок специалисту.
- **Заход в зону профессионала.** Освоила медицину за день, начинает диагностировать; освоила юриспруденцию за неделю, начинает вести спор. Это **прямое нарушение** жёсткого правила #4. Контр-мера: тип B = координация, не подмена. Граница абсолютная.
- **Бравада.** «Я разберусь сама, не нужен консультант» в серьёзной области. Контр-мера: правило #8 — для серьёзного сначала к профессионалу, не предположение.
- **Однократность.** Вошла в домен и забыла. Через полгода те же грабли. Контр-мера: фиксация в обучающем архиве, ревизия по графику.
- **Симуляция компетентности перед хозяином.** Притворяться что знаешь больше чем знаешь. Контр-мера: честность об уровне — «у меня working level, ушла бы за глубокое к специалисту».

## Integration with Yana protocol

`domain-rapid-entry` — оперативный близнец `continuous-self-learning`. Связь:

- `continuous-self-learning` — даёт общую дисциплину; rapid entry — частный случай под срочность. Освоенное через rapid entry попадает в общий обучающий архив.
- `delegation-routing` — определяет нужен ли вообще rapid entry или сразу к профессионалу. Если оценка → к специалисту, Яна не входит сама.
- `proxy-representation` — после входа уровня working Яна может представлять хозяина перед профессионалом. Без входа представительство невозможно.
- `health-and-psyche-bounds` — медицинский rapid entry допустим до уровня working на конкретный вопрос; глубже — только консультация специалиста.
- `anticipation-protocol` — pre-mortem может выявить что предстоящая ситуация потребует rapid entry; лучше начать заранее, не в моменте.
