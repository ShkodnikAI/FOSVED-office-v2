# Отчёт: FORGE-UI-5 — экраны «Ещё» и «Архив отчётов»

Дата: 2026-09-19. Ветка: fo-forge-ui/archive-more → PR → squash в main → деплой Render (авто).
Тесты: 526 → 536 (+10 гвардов/поведенческих UI-5).

## Блок A — экран «Ещё»

- **Сделано.** Три группы по наряду: **Материалы** (Архив отчётов → экран Архива; FORGE · Репозитории → пункт с иконкой из макета `#565045`), **Система** (Интеграции и ключи → существующий экран; Журнал аудита → шит с реальными записями; Требует решения → красный числовой бейдж), **Опасно** (Экстренная блокировка) — красная рамка группы (`danger-group`), физически внизу списка, подальше от повседневных пунктов (гвард проверяет порядок групп в DOM). Плюс сохранена строка Телеметрии (существующий экран, на него ссылается «Главная»).
- **«Требует решения» — сводный пункт.** Реальное число открытых вопросов **разом по всем сущностям**: `forge_gates` (decision IS NULL/'') + `admin_findings` (status='open') — новый читающий эндпоинт `/api/attention` (total = gates_total + findings). Бейдж показывается только при total > 0. Клик — шит со списком открытых гейтов («Гейт #N [kind]: вопрос») и числом находок.
- **FORGE/Репозитории.** Целевые экраны FORGE не строились (по наряду). Пункт НЕ является мёртвой ссылкой: клик открывает честное объяснение — «/repos живёт во внутреннем контуре (mlog serve) и пока не проброшен через публичный прокси — нужен отдельный наряд; файлы FORGE доступны через /preview» (preview-роут FO-037 существует).
- **Журнал аудита.** Существующая таблица `audit_log` (пишется существующей логикой) — новый читающий `/api/audit` (последние 50 записей), шит построчно «время · действие · отдел — детали». Логика `/audit` не менялась.
- **Экстренная блокировка.** Реальное состояние из общей kv (`system_settings: system_lockdown` — та же таблица, куда пишет mlog): в подстроке пункта «Офис активен — блокировка /lockdown в Telegram» или «ОФИС ЗАБЛОКИРОВАН». Клик — шит с честным объяснением: блокировка выполняется командой `/lockdown <пароль>` в Telegram, HTTP-канала нет — из приложения решение не дублируется (логика `/lockdown` не тронута).
- **Версия и хеш внизу экрана** — из реальных данных сборки: `RENDER_GIT_COMMIT` (хеш коммита, переменная окружения Render) + файл `VERSION` (пин бинаря mlog): «офис build a1c264a · mlog 6dcebbe»; без Render-окружения — честный «local».

## Блок B — экран «Архив отчётов»

- **B.1 сделано.** Поиск (лупа) по названию/отделу — существующий серверный поиск `/api/archive?q=` (debounce 350 мс). **Три отдельные прокручиваемые строки чипов** — год, месяц (Янв…Дек), день — построены из реальных дат архива; «все» первым чипом в каждой строке. Выбор в одной строке фильтрует список **клиентски, без перезагрузки** (`renderArchList()` по фильтрам archYear/archMonth/archDay). Пустой период — честное «За выбранный период пусто.»
- **B.2 сделано.** Строки `.arow`: цветной аватар отдела с инициалами (цвет — из реального DEPT_COLORS через существующий `/api/depts/chat`, без хардкода), заголовок, дата в формате «18 сен, 14:22» из реального created. **Пометка контроля** — «⏱ на контроле: <freq>» только у отчётов с реальной kv-записью `control_<doc_id>` (см. «Источник контроля»). **«Изменить»** — честный тост «нужен отдельный наряд (write-эндпоинта нет)» (см. пробел ниже). **Клик по строке** открывает отчёт через существующий sheet (data-report); полноценная страница отчёта — FORGE-UI-6 (следующий наряд), здесь сознательно используется текущий механизм просмотра.

## Источник «на контроль»: какая таблица использована, или зафиксирован пробел

**Использовано существующее**: механизм контроля существует — kv-записи `control_<doc_id>` в `system_settings` (общая kv прокси и Metalogos), пишутся существующими miniapp-действиями `HandleMiniAppAction` (действия «watch»/«control_<freq>»: `kv_set("control_"+doc_id, freq+"|"+title)`). Новый читающий `/api/archive-watches` возвращает их список (только чтение) — пометка в Архиве реальная, не выдуманная.

**Зафиксированные пробелы (не изобретались)**:
1. **Даты окончания контроля нет** — схема kv хранит «freq|title» (daily/weekly/…), а не дату «до 31 дек» из макета. Показана честная форма «на контроле: <freq>».
2. **Изменение периода контроля из UI невозможно** — write-эндпоинта kv control_* не существует (запись идёт через Telegram-мост mlog). Кнопка «изменить» честно сообщает о необходимости наряда; самостоятельная миграция/эндпоинт запрещены нарядом.
