# Redact-контракт (env-secrets) — FOSVED office × Metalogos

Два независимых проекта сошлись на одной семантике редактирования секретов:

- **FOSVED office** — `proxy/redact.py` (наряды FO-021 #87, FO-022 #88);
  применяется: (а) перед upstream-вызовом LLM-провайдера — payload
  `POST /chat/completions`, (б) на каждом ответе Memory-MCP-сервера наружу,
  (в) в текстах ошибок, попадающих в трейсы FO-004.
- **Metalogos №274** (issue #310, taint-инвариант языка mlog) — серверная
  копия того же контракта.

## Контракт

1. **Секретное поле** — имя ключа совпадает с паттерном
   `*_API_KEY | *SECRET* | *TOKEN* | *PASSWORD* | *PASSWD* | *PRIVATE_KEY* | *ACCESS_KEY* | *CREDENTIAL*`
   (регистронезависимо, разделители `_`/`-`) **и** значение — строка ≥ 8 символов.
   Значение поля заменяется на `[REDACTED]` на любой глубине структуры
   (dict / list / вложенные JSON).

2. **Литеральное значение секрета** (второй контур, FO-022) — множество
   значений известных секретов собирается из env-переменных и `secrets_store`
   (имена которых совпадают с паттерном п.1, значение ≥ 8 символов). Каждое
   вхождение значения в **любую строку** структуры (в т.ч. внутри системного
   промпта / сообщения) заменяется на `[REDACTED]`.

3. **Перестройка при смене ключа** — множество значений не кэшируется дольше
   5 секунд; после ротации ключа (`invalidate_values_cache()` или истечение
   TTL) redactor подхватывает новое значение автоматически. Ротация не
   требует рестарта и не требует правки кода.

## Инварианты (тест-кит FO-022)

- Payload с секретом не уходит наружу: ни как значение секретного поля,
  ни как литеральная вставка в текст (инвариант, тест `test_redact_invariant_upstream`).
- Redactor перестраивается при смене ключа (тест `test_redactor_rebuilds_on_key_change`).
- Трейсы не содержат секретных значений (ошибки провайдеров проходят redact
  перед записью).

  у офиса Telegram-транспорт.
