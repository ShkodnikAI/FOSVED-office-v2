# Журнал проверки. Ревью плана реализации офиса (02.11.2026)

**Что исполнено:** обновлённый модуль контракта «Карточка» на таблицах прода
(`dept_archive` / `dept_verification` / `dialog_history` / `system_settings`) —
решение D1, — пять примеров аудита, портированных на него, и семь проб, каждая
из которых доказывает конкретный вердикт ревью.

**Рантаймы:** `mlog 0.38.0` (цель наряда #620) и `bin/mlog 0.34.1` (текущий прод
офис). Оба прогона обязательны: `mlog test` не падает на статической ошибке в
невызванном паттерне, а `mlog check` не исполняет ветки — поэтому везде в паре
`check` + `test` (урок аудита §5.2).

**Как воспроизвести:**

```sh
export DATABASE_URL="sqlite::memory:"
sh deliverable-review/examples/run_all.sh      # 6 файлов × 2 рантайма
sh deliverable-review/probes/run_probes.sh     # 7 проб × 2 рантайма
```

**Код в репозиториях не менялся.** Все файлы — в `deliverable-review/`, снимок
репозитория `work/o2/` читался только на чтение.

## 2. Намеренно красный тест

`probes/probe_a2_parsejson.mlog` — **0/1 passed, и это доказательство, а не брак.**
Проба повторяет форму прода `dept/legal.mlog:794-800` после наивной замены
`db_execute("SELECT …")` → `query(…)`:

```
❌ форма прода после наивной замены db_execute→query:
   [TYPE_MISMATCH] parse_json() expected String argument, got List
```

`mlog check` при этом отвечает `OK: no issues found` — статика ошибку не видит,
она возникает только в рантайме. Вывод для наряда A2: починка 24 сайтов **не
сводится к поиску-замене вызова**, каждый сайт требует переделки разбора
результата и собственного исполняемого теста.

## 3. Что доказывает каждая проба

| Проба | Вердикт | Доказанный факт |
|---|---|---|
| `probe_a2_sites` | A2, поправка 5 | `db_execute("SELECT")` данных не возвращает; `try` перехватывает отказ (`TryVal = "()"`); MySQL `INTERVAL '90 days'` не проходит **и через `query()`**; диалект SQLite возвращает данные; замена CTE+INSERT на `while`-цикл даёт те же 4 строки |
| `probe_a2_cte` | поправка 5 (опровержение) | `quest.mlog:24` (CTE+INSERT) **работает**: `db_execute` отказывает только когда запрос возвращает набор строк → прод-счётчик сломанных сайтов **24**, а не 26 |
| `probe_a2_parsejson` | A2 (стоимость) | наивная замена даёт runtime `TYPE_MISMATCH`, `check` молчит (см. §2) |
| `probe_d3_loader` | D3, поправка 2 | прод-загрузчик `context.mlog:213` грузит **2 скилла из 10** (29 370 символов при бюджете 25 000, +17%); `osp.mlog:833` — **1 из 10** (15 409 при бюджете 12 000, +28%); проверка бюджета ПОСЛЕ добавления даёт **1 из 10**; нарезка «ядро 1500 + приложение 9000» — **10 ядер + приложение = 24 313 ≤ 25 000** |
| `probe_d3_ladder` | D3 | «лесенка секций» на реальных 24 `SKILL.md`: L1 = 6 066, L2 = 19 437, L3 = 32 237, L4 = 80 163 символа; загрузчик сам выбирает уровень по бюджету и на всех глубинах 0–4 грузит **10/10 ядер в пределах бюджета**; полных ядер (L4) в бюджет depth=3 входит **3 из 10** → критерий приёмки B1 «≥6 скилл-ядер» недостижим |
| `probe_d4_tail` | D4 | структурный хвост извлекается программой и проверяется `json_validate` (LLM не зовётся): валидный хвост → `OK`, битый JSON → `FAIL` (не «голый ответ»), `kind` вне словаря и отсутствие `verify_by` → `FAIL` с точным путём поля, хвоста нет → `BARE`; чек-лист артефакта строится из `file_exists`/расширения/реестра `visual_artifacts`; `json_validate` и `file_exists` доступны **и на 0.34.1** |
| `probe_number_format` | D6 | `to_string(Float)` не даёт хвоста `.0` (`to_string(4.0) = "4"`), формат владельцу — `to_string(round(x*100)/100)` → `5.26` |

## 4. Девять новых тестов модуля v2

| Тест | Что фиксирует |
|---|---|
| D1: ноль новых таблиц, 20 колонок, миграция идемпотентна | `sqlite_master` не содержит `dept_card*`; повторный `CardMigrate()` = `added=0`; колонки действительно появились (`pragma_table_info`) |
| D1: legacy `/verify` идёт через автомат | `CardVerifyDispatch("actual=…")` → `resolved`, статус `verified` (app.mlog:1224) не появляется; свободный текст отвергается; чужой вид исхода отвергается |
| D2/инвариант 5: контуры не смешиваются | `CardScore` считает только `contour='owner'`; переход статуса не меняет `contour`; неизвестный контур отвергается до записи |
| D2: кардинальность bench | `CardBenchCards(150, 5, "details") = cards=0|details=750`; альтернатива `cards` = 750 карточек в общем столе |
| D1: сирота невозможна | `FOREIGN KEY(archive_id)` отвергает факт без карточки; карточка без `claim_json` находится счётчиком `CardEmptyClaims()` |
| D1: ScoreDept без правки слеп | legacy-счётчики `verified=0|drafted=0` при живой карточке; `CardScoreBlock` показывает реальное состояние |
| D1: журнал ответов без новой таблицы | покрытие считается из `dialog_history` (туда уже пишет шов, app.mlog:592-599) |
| D1: legacy MAPE оживает | запрос байт в байт как app.mlog:1260 возвращает 10 пар `forecast_value`/`actual_value` после записи карточек |
| v2-самопроверка: факт = 0 | невычислимая пара исключается из знаменателя MAPE и сообщается отдельно (баг, найденный в собственном v1 и в проде app.mlog:1270-1278) |
