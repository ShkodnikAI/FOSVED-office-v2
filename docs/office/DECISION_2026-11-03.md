## Ответы на вопросы §8.2 ревью

1. **Бюджет скиллов — экономия не цель.** Цены моделей низкие; ограничитель — окно контекста и качество, не деньги. Бюджеты загрузчика: quick (depth 0) → L2; default/regime (1) → L3; wargame/deep/full (2–4) → **L4 (полная методология, ~85 000 символов)**. Уровни затем сравниваются A/B на бенчмарке ОСП (W4), решение о понижении — только по измерению. `daily_budget_<dept>` остаются **предохранителем от сбоя**, не экономией: ОСП 10.00, остальные 3.00 USD/день.
2. **Разметка 100–200 текстов:** агент готовит кандидатов из `dialog_history`/`trace_log`, владелец утверждает; набор `route_eval_set` с версией; срок — конец фазы A.
3. **Тренировочные прогнозы в общий архив не пишутся.** Правило различения — по источнику, а не по содержанию (см. ниже).

## D9 (новое). Стандарт ответа владельцу — для всех отделов и Яны

Владелец требует: **кратко, по сути, с важными акцентами, максимально таблицы и инфографика.**
- Структура: 1–3 строки вывода → таблица (если сравниваются ≥3 объекта или ≥3 числа) → акценты (≤5 пунктов) → детали по запросу.
- Числа — программой и в формате `round(x*100)/100`; временные ряды и доли — картинкой (`chart_line`/`chart_bar`/диаграммы Metalogos), не текстом.
- Проверка — программная, предупреждением (поправка 2: блокируется только форма карточки, не стиль): длина первого блока, наличие таблицы при ≥3 числах, сырые числа с >2 знаками после запятой.
- Метрика: доля ответов, прошедших проверку формы, — в `/office` и `/score <dept>`.

## Различение «тренировочное / архив» (ответ на вопрос 3)

| | Архив (работа отдела) | Тренировка (бенчмарк) |
|---|---|---|
| Откуда вопрос | владелец (Telegram, команда отдела) или Яна по поручению владельца | машина: `OSPBenchIngest` из ForecastBench |
| Где хранится | карточка `dept_archive` (`contour='owner'`) + детали `osp_forecast` (`kind='owner'`) | только `osp_forecast` (`kind='bench'`, `bench_qid` заполнен) |
| Кто ставит метку | код пути создания, в момент создания; поле не меняется (инвариант 5) | то же |
| Что видит владелец | `/osp score`, `/score`, `/archive`, утренняя сверка | отдельный блок «тренировка» в `/osp score` (Brier, калибровка); в поиске и сверке не появляется |
| Исход подтверждает | владелец | автоматически из `resolution_set` |

Тест‑инвариант: ни одна строка `dept_archive` не имеет `bench_qid`; ни одна `osp_forecast` с `kind='bench'` не имеет `card_id`.
