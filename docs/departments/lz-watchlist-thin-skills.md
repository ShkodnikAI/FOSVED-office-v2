## 1. Определение

Для агентских харнесов, у которых тулы уже есть, компактный скилл-роутер («тип задачи → самая быстрая команда») вытесняет толстые декларативные tool-слои по токенам, ходам и стоимости при сопоставимой точности. Суть инженерного принципа — **минимальная декларируемая поверхность инструментов**: агент читает короткий роутер и сам вызывает нужную CLI/API-команду, вместо того чтобы нести в контексте сотни деклараций тулов на каждый чих.

## 2. Как есть (на 19.10.2026)

- MCP де-факто стандарт интеграций агентов; tool-слои харнесов несут полные декларации тулов в контекст.
- Лучший случай толстого слоя — deferred tool search (отложенная загрузка объявлений тулов): по бенчмарку lean-проекта разница с тонким скиллом почти исчезает (34.9k vs 34.5k токенов на тривиальном «Reply OK»). **Это контраргумент №7, не подтверждение тренда** — тонкий слой обязан выигрывать не только у худшей конфигурации толстого (all-tools-loaded).
- Скилл-роутеры существуют как периферийная практика (доменные SKILL.md без MCP-слоя).

## 3. Как будет (если тренд материализуется)

- Узкие скилл-роутеры на домен задач (рекон/биоинфо/финансы/…) как обычный способ подключения агентских поверхностей.
- Tool-поверхности харнесов сокращаются; он-demand skills становятся first-class.
- MCP смещается на бэкенд-интеграции с чужими сервисами, а не на прямую поверхность агента.

## 4. Границы (что тренд НЕ означает)

- Не «смерть MCP» как протокола интеграций: спека решает интероперабельность, а не контекстную экономику.
- Неприменим там, где тулы реально отсутствуют у харнеса (скилл-роутер роутит существующие команды, он не создаёт возможности).
- Неприменим к задачам, где нужен динамический поиск по огромной поверхности тулов, если CLI-эквивалентов нет.

## 8. Competing alternatives (правило №7 устава)

Тренд сверяется против трёх линий-конкурентов:

1. **MCP + deferred tool search** — контраргумент «толстый слой в best-case почти бесплатен» (34.9k vs 34.5k токенов). Тренд подтверждается, только если thin-skills выигрывает не только у худшей конфигурации толстого слоя (all-tools-loaded).
2. **Встроенный tool-use уровня модели** — провайдеры сами оптимизируют контекст тулов (parallel tool use, нативный tool selection); тогда отдельный роутер-слой не нужен.
3. **Харнес-нативные плагин-системы** — харнесы строят собственные механизмы загрузки расширений (плагины, расширения, MCP-клиенты с фильтрацией) и поглощают нишу скилл-роутеров изнутри.
