# Finance — переосмысление под нативный Metalogos

Статус: **первый проход завершён**, 2026-09-24. Проверено чтением
профиля (`library/finance.md`) + кода (`dept/finance.mlog`, 1462
строки) + реальным grep по проекту, не по памяти.

## Миссия (без изменений — формулировка профиля точна)

Ведение финансового состояния бизнеса: прогноз cashflow, инвойсы,
unit economics, налоговый комплаенс по явной юрисдикции, MRR/ARR для
подписочных продуктов. Готовит данные для бухгалтера, не подменяет
его.

## Жёсткие правила (7) — сверено с кодом, актуальны, не трогать

Verification date обязателен, юрисдикция всегда явная, не подменяет
бухгалтера, не пересчитывает задним числом, копейки не округляются,
не подаёт декларации, не даёт инвестиционных советов. Все семь —
методологически корректны для финансового отдела, конфликтов между
собой не нашёл (в отличие от того, что модуль methodology-
contradiction-finding из отдела Аудита обычно ищет).

## Находка — платформенное наследие, требует правки

**Раздел "Archive integration" в профиле** описывает несуществующий
механизм:

> "Все результаты публикуются в `ARCHIVE_CHANNEL_ID` через
> `lib/archive-publisher.js`. Каждая запись `FinancialForecast` имеет
> `archiveMessageId` + `archiveChannelId`"

Это язык старой (до-Metalogos) платформы — `.js`-путь физически не
может исполняться в текущем стеке. Проверено: `dept/finance.mlog` НЕ
содержит ни одного упоминания `archive-publisher`, `ARCHIVE_CHANNEL_ID`,
`archiveMessageId`. Реальный путь (`app.mlog:5190`) — тот же `SendReport`,
что и у всех остальных отделов, ведущий в `miniapp_responses` +
Mini App, не в отдельный Telegram-канал.

**Решение (предлагается, не окончательное):** переписать раздел
"Archive integration" на честное описание реального механизма —
`SendReport` → `miniapp_responses` → доступно через `/miniapp/<doc_id>`
и Архив в Mini App. Убрать `archiveMessageId`/`archiveChannelId` как
поля модели данных, если они нигде реально не используются (проверить
отдельно — не проверял на этом проходе).
