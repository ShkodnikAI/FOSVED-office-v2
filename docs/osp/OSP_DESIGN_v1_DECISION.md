# Решение владельца по OSP_DESIGN_v1 (02.11.2026)

Принят **вариант A «Карточка»** (`OSP_DESIGN_v1.md`) с четырьмя поправками. Поправки имеют приоритет над текстом дизайна.

## Поправки

1. **Базовая частота — вход модели, не механическое сжатие.** `OSPBlendPrior`/`OSPPriorWeight` (§2, §9.3) по умолчанию выключены. Базовая частота подаётся в промпт каждого прогона ансамбля. Механическое сжатие включается только по правилу Platt (§5.2): выигрыш ≥0.005 Brier на отложенной выборке, иначе выключено. Класс сравнения — не «тема», а вопросы того же типа (источник/вид исхода); при n<10 — не применяется. Основание: в примере §9 сжатие к «теме» подняло p с 0.084 до 0.202 при рынке 0.03.
2. **G6 «расхождение с рынком» — предупреждение, не блокировка.** Порог 0.35 переводится в W6: публикация разрешена, но обязательно поле `market_dissent_reason` (структурное, ≥1 проверяемый аргумент); отсутствие обоснования — блокировка G6′. Обоснованное несогласие с рынком — ценный продукт отдела.
3. **Бенчмарк гоняет тот же конвейер, что и прогнозы владельца.** Никакой «дешёвой тройки» для bench: те же модели, те же скиллы, те же гейты. Объём — стратифицированная выборка 100–150 вопросов раунда (не все 1500 строк). Метрики и Platt переносимы на owner-контур только при этом условии; любое расхождение конфигурации пишется в `models_json` и делает строку непригодной для калибровки owner.
4. **Критерий успеха (2 месяца):** ≥50 разрешённых прогнозов с программным Brier; owner-контур показывается отдельной строкой с честным n (без требования ≥25).

## Ответы на B.1–B.5
- B.1 ForecastBench — официальный тренировочный поток: **да**. Metaculus API — нет.
- B.2 Лидерборд первые 3 месяца: **нет**.
- B.3 `daily_budget_osp` = **2.00 USD/день** (с учётом поправки 3).
- B.4 Исход owner-прогноза подтверждает **владелец**; bench — автоматически из `resolution_set`.
- B.5 Цели Brier → **skill score** (год 1: skill vs 0.25 ≥ +0.10 при n≥50 и Brier ≤ Brier рынка на тех же вопросах).
