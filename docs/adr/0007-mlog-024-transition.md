# ADR-0007: Переход боевого бинаря Metalogos с 0.23.0 на 0.24.0

**Статус:** принято (N024 — прямое указание владельца, 2026-09-25: «У нас
релиз Металогос уже 0.24.0. переходим на него»)
**Дата:** 2026-09-25
**Контекст решения:** открытый наряд-issue отсутствует (переход — прямое
указание владельца в чате; soak-наряды #323/#182 переход не содержат).
0.24.0 = Wave 14 (squash 5df35ff, release naryad №447): `forget` — реальный
хендлер забывания (грант ADR-0155, каскад derived-from → poisoned, ledger
`memory.forget`), decay/boost/retain-ttl в typed-лейне, registry 499→500
(`memory_retain_ttl` в конце — **аддитивно, контракт .mbc-индекса
сохранён**), static check_id 33→35, P0-readiness 80→82%. Все изменения
языка-поверхностей аддитивные; ломающих CHANGELOG не заявляет.

**Сборка:** в отличие от ADR-0005/0006 (сборка из тега), бинарь 0.24.0
взят **из официального CI upstream**: workflow «Build and Release» на
коммите тега `v0.24.0` (5df35ff, run 36036599560, job build success),
артефакт `mlog-linux-x86_64` (32 249 032 байта, ELF x86-64, not stripped).
`mlog --version` → `mlog mlog 0.24.0`. Rust-тулчейна в песочнице на момент
перехода нет (окружение сбрасывалось между сессиями) — CI-артефакт
предпочтительнее установки тулчейна: идентичная воспроизводимость
апстримному тегу, ноль локальных отклонений компиляции.

## Решение

**`bin/mlog` = 0.24.0.** Guard-цепочка entrypoint сохранена без изменений
механики: кандидат = `bin/mlog`, проба audit на аугментированной копии
(мост №421), бут-фолбэк = `bin/mlog-020` (0.20.0). **`bin/mlog-023`
вендорен как прошлый-хороший/тест-гвард** (роль mlog-022 из ADR-0006
переходит к нему); **`bin/mlog-022` выведен из репо** (восстанавливается
из git-истории, прецедент mlog-021 из ADR-0006). bin/ несёт 0.24 + 0.23 +
0.20 (~86 МБ, вес ротации не изменился).

## Что проверено (методология ADR-0005/0006, блоки B.2–B.5)

1. **Статика `check app.mlog`:** 694 строки — **байт-идентично**
   0.23↔0.24 (0 parse error; rc=1 — известный базлайн без parse errors).
2. **Статика `audit`:** raw (rc=1, те же 42 строки [ERROR] долга №327,
   0 Category A) и с мостом №421 (`profile legacy {
   egress: permissive_with_audit }`, rc=2, 0 [ERROR]) — **байт-идентичны**
   0.23↔0.24. Гвард-проба entrypoint на кандидате пройдёт (aug rc=2).
3. **Гвард dept-модулей:** все 27 `dept/*.mlog` на 0.24 — rc≡0.23,
   выводы байт-идентичны, 0 строк [ERROR].
4. **Байткод:** `compile app_aug.mlog` rc=0 на обоих; размер байткода
   совпадает (1 840 965 байт). **Перекрёстное исполнение .mbc** (пробник
   `scripts/probe024/probe.mlog`: each/try/структуры/строки):
   023.mbc@0.24 ≡ 024.mbc@0.24 ≡ 023.mbc@0.23 ≡ 024.mbc@0.23 (rc=0,
   вывод эквивалентен) — claim CHANGELOG «append-only, the .mbc index
   contract» подтверждён на офисной поверхности.
   Методологическое примечание: байт-в-байт сравнение .mbc **между
   версиями невозможно и не требуется** — constant-pool компилятора
   рандомизирован per-process (проверено: два прогона одного бинаря дают
   разный порядок пула на ОБЕИХ версиях; то же для порядка полей Struct в
   `[print]` — рандом per-process, не регресс 0.24).
5. **Serve-батарея (B.3):** полный стек на интерпретаторе (мост, env-
   allowlist ценза, sqlite), **35 декларированных роутов app.mlog +
   health** — пробы GET (secret+Bearer) и POST: коды и тела (префиксы
   240 Б) **идентичны 0.23↔0.24** (7×200 / 1×400 / 22×403 / 3×404 /
   2×500; 403 — /cron/* и /schedules/* без боевых секретов стенда,
   500 — известные артефакты стенда /repos*/respond_html, 404 —
   пустая БД). Бут-маркеры идентичны: backend interpreter, [db]
   Connected, listening. Стенд: `scripts/probe024/serve_battery.sh`.
6. **VM-паритет (B.1-гвард):** METALOGOS_SERVE_BACKEND=vm — бут
   идентичен ([db] Connected, backend vm, listening); /health 500,
   / 200, webhook — «RecallLearnings expects 2 args» — **те же
   пре-существующие VM-гэпы, задокументированные в Task 70**
   (db_decl-нелитеральный URL + невайринг кросс-модульных индексов).
   Регресса 0.24 нет; продовый путь — интерпретатор (пин entrypoint).

## Что намеренно НЕ включено

- Новые возможности 0.24 (`forget`, `memory_retain_ttl`, decay/boost/
  retain-ttl-опции `memory_put`) — потребность не заявлена; отдельные
  наряды. Каскад забывания (№445) — кандидат в будущую методологию
  памяти офиса (консент-гейты уже совместимы с №413-контрактом).
- Выведение mlog-020 из ротации (ADR-0006 оставлял это условным): VM/
  interpreter-гарантии 0.23–0.24 в проде ещё не прошли soak; фолбэк
  сохраняется до гейта ADR-0141.
- Миграция долга №327 и снятие моста №421 — долг сохраняется (42=42).

## Последствия

- Прод едет на 0.24 с прежней guard-пробой; откат: в entrypoint
  `MLOG_BIN=./bin/mlog-023` (прошлый-хороший) или `./bin/mlog-020`
  (аварийный).
- Гейт ① кутовера cron («native schedules OK» в бут-логе) проверяется
  на буте 0.24; cron-job.org не трогается до двух зелёных гейтов.
- CI-путь апгрейда задокументирован: при следующих релизах бинарь
  брать из «Build and Release» артефакта тегового коммита (проверять
  `--version` = тег) — сборка из тега в песочнице требует установки
  Rust-тулчейна и даёт то же самое.
- Бут-шум `[REDACT][audit-event]` сохраняется (класс 0.22+, безошибочный).
