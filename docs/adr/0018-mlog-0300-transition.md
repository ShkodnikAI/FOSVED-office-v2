# ADR-0018: Переход боевого бинаря Metalogos с 0.29.0 на 0.30.0 (релиз-гейт 0.30 GREEN: parameterized share, VM-паритет сравнений №629, compile-time отказы №617)

**Статус:** принято (прямое указание владельца «Переходи на релиз Metalogos
0.30.0», 2026-10-08; исполнение — наряд-конвейер, база main @ `23156f9`).

**Контекст решения:** Metalogos v0.30.0 (тег, published 2026-10-08 06:55 UTC,
source commit `6eafee1c`) — релиз, закрывающий гейт 0.30 (parameterized
share ≥ 5000 bp, OWNER-FIXED 2026-10-07, ADR-0186 §5 — факт 6043 bp, 55/91;
open High findings (server path) = 0; branch-protection-критерий В34 Z-3 —
GREEN; публикация — акт владельца по чат-вердикту «публикуй», прецедент
v0.29.0). Это первый переход, потребовавший **офисной ремедиации корпуса**
со времён ADR-0015: №617 ввёл compile-time отказы, вскрывшие один реальный
баг и одну лексерскую мину, плюс легализовал столкновение с шаблонным
препроцессором 0.23.

## Состав релиза, значимый для офиса

- **№617 (gh#1075), три compile-time отказа семантики:** walk областей
  видимости (модель TW-env — плоская, без pop), отказ чтения
  undefined-переменной (код `UNDEFINED_VARIABLE`), отказ присваивания
  в undefined, статическая opaque-конкатенация. На офисном корпусе
  вскрыто 6 находок в 4 файлах — ремедиация ниже.
- **№629 (gh#1096), security, fail-closed — VM-паритет операторов
  сравнения:** `==`/`!=`/`>`/`<`/`>=`/`<=` на VM теперь 1:1 матрица TW;
  гетерогенное равенство (`"abc" == 5.0`), упорядочивание не-Float пар
  и несравнимые типы (Struct/List/Html) ОТКАЗЫВАЮТ со стабильным
  `[TYPE_MISMATCH]` на обоих бэкендах (легаси-VM отвечала тихим `false` —
  класс «молчаливо-неверных гвардов» X-1/Y-1/Q-1). Найдено фаззером №621.
  Боевой офис — интерпретатор (TW-матрица не менялась); для VM-стейджинга
  (FO-050) — честный fail-closed вместо тихой лжи.
- **№622 (gh#1085):** `return` внутри arm `match`/`if`-выражения —
  значение arm'а на обоих бэкендах (TW-контракт теперь держится и на VM).
- Прочее: №630 (дефолт-цель unfreeze_gate 0.29 → 0.30), №616/№631/№623/№627
  (типизация реестра — внутренние), №633 (dead_code 33→15), №634/№635
  (self-host lexer / VM template_render lanes), №618 (Kamerton-cycle
  отчёт по v0.29.0).

## Офисная ремедиация (№617-индуцированная)

1. **`dept/qa.mlog:937` — реальный баг:** `AuditLog(..., "Defects listed" +
   statusFilter)` склеивал audit-строку с никогда не существовавшей
   переменной `statusFilter` (на 0.29 — молчаливое undefined-чтение).
   → честный лог фильтров: `"Defects listed (open=" + f_open + ",
   critical=" + f_critical + ")"`.
2. **`dept/qa.mlog:1246/1261` — лексерская мина:** идентификатор
   `falsePositiveRate` лексер рвёт по ключевому слову `false` → walk видит
   undefined `PositiveRate` (минимальный репро — 5 строк). Пусть и
   использование лексировались одинаково (программа работала), но имя
   легально невозможно. → переименование в `fp_rate`.
3. **`dept/templates.mlog:3–4`, `dept/dev.mlog:1622/1847`,
   `dept/visual.mlog:643` — триггер шаблонного препроцессора 0.23:**
   слово t* в сыром тексте (включая комментарии) переписывает следующий
   строковый литерал в слот `__TEMPLATE_BODY_N` → №617 честно отвергает
   undefined-слот (класс столкновения известен с наряда #366).
   Комментарии переписаны без t-токена.
4. **`dept/visual.mlog:644/646` — командная строка `/visual-template`:**
   имя команды сохранено байт-в-байт разрывом токена конкатенацией
   `"/visual-templ" + "ate"` (runtime-значение идентично, вывод команде
   не меняется); сопутствующий тест test_n379 обновлён на новую форму
   исходника с пояснением.

## Следствия

1. CI-гвард №312 (audit dept) по-прежнему rides `bin/mlog-0271`;
   parse-гейты — `bin/mlog` (0.30.0), теперь с семантикой №617 — класс
   «undefined variable» ловится на PR до мержа.
2. Гвард версий обновлён: test_n399_a2_llm_757 A.2.1 — 0.30.0 + sha256
   артефакта (`fe6215cb…`).
3. Деплой владельцем на Render подхватит 0.30.0 автоматически; ожидание
   бут-лога — как в ADR-0017 (guard-проба rc=2, «native schedules OK»,
   /version OK).
4. FO-050 (office#182): с 0.30.0 на VM-бэкенде гетерогенные сравнения
   отказывают громко (`[TYPE_MISMATCH]`) — поведение по контракту №629.
   VM-проба перехода на 0.30.0 ответа не дала: в песочнице бут не дошёл
   до строки `backend:` за ~5 минут (компиляция корпуса; на 0.29.0 в
   ADR-0017 проба доходила до backend+Connected с известным разрывом
   DDL-bootstrap 0 таблиц vs 134). Статус разрыва на 0.30.0 не
   перепроверен — VM-флип и его перепроверка за владельцем.
