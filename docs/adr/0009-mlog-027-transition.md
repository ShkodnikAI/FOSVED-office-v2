# ADR-0009: Переход боевого бинаря Metalogos с 0.25.0 на 0.27.0

**Статус:** принято (прямое указание владельца «у нас новый релиз 0.27.0,
переходим на него», 2026-09-27; прецедент: №349→ADR-0005, №353→ADR-0006,
N024→ADR-0007, №372→ADR-0008)
**Дата:** 2026-09-27
**Контекст решения:** Metalogos v0.27.0 = unfreeze-релиз (squash 0d1cce9,
релиз-наряд №494, гейт gh#680 поднят владельцем Metalogos 2026-09-27,
комментарий 5851623870). Состав перехода 0.25.0 → 0.27.0 — ТРИ релиза:
- **0.26.0 «Security by Default»** — закрытие всех находок аудита 25.09
  (Волна 16): №454 mock-LLM fail-loud; №455 file-ingest gate (deny-list
  `.env*`/`*.db`/`*.sqlite*`/`.git/**`/`*.mlog`/`metalogos.toml` + serve-
  containment в `METALOGOS_DATA_DIR` + escape-crane
  `METALOGOS_SENSITIVE_PATH_ALLOWLIST`); №457 инверсия умолчания
  exec-контекста в serve (всё — serve-route, кроме явной зоны регистрации);
  №458 HARDCODED_SECRET категории A (provider-формат литералов отказывает
  компиляцию); №459 gitleaks/cargo audit в CI.
- **0.26.1** — Wave 17 (7 стратегических решений гейта gh#680), без кода.
- **0.26.2** — Wave 18 (дедуп TW/VM 60→20, enum Type stage 1 WARN-ONLY).
- **0.27.0** — снятие доменной заморозки ADR-0177 владельцем.
Ключевое для офиса: В17-фиксы памяти (находки FO-056, office#386 —
GRANT_SCOPE_MISMATCH/retained-TTL/anchored_start приняты апстримом;
E2E-фикстура офиса перегнана на 0.26.1 в наряде №475 — 16/16 + 3/3).

**Сборка:** бинарь 0.27.0 взят **из официального CI upstream** (путь
ADR-0007/0008): workflow «Build and Release» на squash-коммите тега
`v0.27.0` (0d1cce9), артефакт `mlog-linux-x86_64` (33 940 480 байт,
ELF x86-64, sha256 b84c04060764055ffc74cc606067a02983221ba66c3bd8176027e117821c6a4c).
`mlog --version` → `mlog mlog 0.27.0` (grammar rev: 1).

## Решение

**`bin/mlog` = 0.27.0.** Guard-цепочка entrypoint сохранена без изменения
механики: кандидат = `bin/mlog`, проба audit на аугментированной копии
(мост №421), бут-фолбэк = `bin/mlog-020` (0.20.0). **`bin/mlog-025`
вендорен как прошлый-хороший/тест-гвард** (роль mlog-024 из ADR-0008
переходит к нему); **`bin/mlog-024` выведен из репо** (восстанавливается
из git-истории, прецедент mlog-022/023). bin/ несёт 0.27 + 0.25 + 0.20.

**№455-адаптация (главное решение перехода).** Serve-чтения файлов в 0.26+
содержатся в `METALOGOS_DATA_DIR` (дефолт `./data`); office-корпус читает
~100 ресурсов приложения из корня (skills/**, library/**, config/,
VERSION, METHODOLOGY.md) плюс *.mlog-снапшоты (app.mlog, dept/*.mlog,
library/{personas,brand}.mlog, memories/consensus.mlog) — прямая миграция
в data/ = правка ~100 сайтов чтения с риском регрессий на обеих версиях.
Принято (entrypoint, блок «№455»): **`METALOGOS_DATA_DIR` = корень
приложения** (`.`) + **загрузочный allowlist .mlog-имён**
(`METALOGOS_SENSITIVE_PATH_ALLOWLIST` генерируется entrypoint'ом из
dept/library/memories). Следствия, честно:
- layer-1 deny-list сохранён ПОЛНОСТЬЮ — `.env*`/`*.db`/`*.sqlite*`/
  `.git/**`/`metalogos.toml` не читаются никогда (строже 0.25, где гейта
  не было вовсе); чтения *.mlog снимаются с deny-list по имени, контент
  помечается Secret движком меток и на каждом сайте обёрнут
  в `redact(..., "all")` (как и было);
- containment-инвариант layer-2 сознательно сдвинут с `./data` на корень
  приложения: ресурсы приложения — деплой-артефакты (не секреты; секреты
  приходят через env-гейт №259), поэтому residual-риск сведён к чтению
  несекретных исходников при гипотетической инъекции в роут. Переезд на
  ./data со снапшотированием ресурсов — отдельный наряд, если владелец
  сочтёт нужным;
- рантайм-записи (`config/priority_*.txt`, `memories/consensus.mlog`,
  `config/override_<dept>.txt`) гейту №455 не подчиняются (проверено по
  исходникам 0.27.0: `write_file`/`append_file` не вызывают
  `file_ingest_gate`) — поведение идентично 0.25.

Сопутствующее: CI-гвард №312 (`.github/workflows/ci.yml`) переведён с
выведенного `bin/mlog-024` на `bin/mlog-025` (совместимость обоснована
B.2.3: аудит dept на 0.25 байт-идентичен боевому 0.27). Аналогично
обновлены pytest-гварды `test_binary_prev_good_vendored`
(tests/test_schedules_native.py), `VENDORED_BINARIES`
(tests/test_binary_exec_bit.py), пары дуально-бинарных проб
(test_n384_yana_delegation, test_fo376_osp_auth).

## Что проверено (методология ADR-0005/0006/0007/0008, блоки B.2–B.4)

1. **Статика `check app.mlog`:** rc=1 (известный базлайн, 0 parse error)
   — вывод **байт-идентичен** 0.25↔0.27.
2. **Статика `audit`:** raw (rc=1, те же 42 строки [ERROR] долга №327,
   0 Category A — security-волна 0.26.0 НЕ добавила офису ни одного
   нового Category-A отказа) и с мостом №421 (`profile legacy {
   egress: permissive_with_audit }`, rc=2, «32 warnings, 304 passed») —
   **байт-идентичны** 0.25↔0.27. Гвард-проба entrypoint на кандидате
   пройдёт (aug rc=2).
3. **Гвард dept-модулей:** все 27 `dept/*.mlog` — check на 0.27, rc и
   выводы байт-идентичны 0.25 (27/27, 0 различий).
4. **Байткод:** `compile` аугментированной копии rc=0 на обоих; размер
   .mbc совпадает (1 883 327 байт). **Перекрёстное исполнение .mbc**:
   app-байткод (025/027) × (0.25/0.27) — 4/4 rc=0. Поведенческий пробник —
   FO-056-фикстура `test_memory_fo056.mlog` (16 меток): 16/16 PASS на
   обоих бинарях; выводы идентичны после нормализации случайных ID
   (mem- session, grant, batch) и wall-clock deadline — детерминированные
   поля (хэши, счётчики, вердикты ledger_verify) совпадают байт-в-байт.
   Методологическое примечание ADR-0007 в силе: байт-в-байт сравнение
   .mbc между версиями невозможно и не требуется (constant-pool
   рандомизирован per-process).
5. **Serve-батарея (B.3/B.4):** полный стек (llm_proxy + mlog serve +
   reverse proxy) на интерпретаторе (мост, env-allowlist ценза, тестовый
   sqlite) — /health (прямой и через прокси), /version, webhook /status,
   /osp/analyze (ping + боевой), эксперт-запрос, /lz, /cron/control,
   /schedules/list — отчёты **идентичны** 0.25↔0.27 (после №455-адаптации;
   до адаптации 0.27 громко отказывал read_file VERSION/library/*.md —
   ровно по спецификации №455, что и стало триггером адаптации). Инверсия
   serve-контекста №457 surface офиса не изменила (cron-тики под
   ServeRouteExecGuard — отчёты /cron/control, /schedules/list идентичны).
6. **№454/№458/№459:** mock-LLM fail-loud — офис работает на реальном
   LLM-прокси (:4000), METALOGOS_MOCK_LLM не задаётся; provider-формат
   секретных литералов — raw-audit 42=42 (новых Category-A нет); gitleaks —
   предмет CI upstream.

## Что намеренно НЕ включено

- Выведение mlog-020 из ротации (ADR-0008 оставлял условным): VM/
  interpreter-гарантии в проде ещё не прошли soak (FO-050/#182 — вариант-А
  ждёт апстрим-фикс VM-компилятора db_decl env()-деклараций); фолбэк
  сохраняется до гейта ADR-0141.
- Переезд офисных ресурсов в ./data (снапшотирование) — осознанно
  отложен (см. №455-адаптацию); отдельный наряд при желании владельца.
- Новые возможности 0.26/0.27 (enum Type, дистилляция-гейты, forecast-
  поверхность) — потребность не заявлена; усыновление по мере надобности.
