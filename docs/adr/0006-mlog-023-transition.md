# ADR-0006: Переход боевого бинаря Metalogos с 0.22.0 на 0.23.0

**Статус:** принято (N023 — прямое указание владельца, 2026-09-24)
**Дата:** 2026-09-24
**Контекст решения:** владелец: «Сначала перейдем на бинарник 0.23.0» (в
issues отдельного наряда нет — открытые #323/#182 не содержат перехода).
Сборка из тега `v0.23.0` (ShkodnikAI/Metalogos-, squash 23323f0a, release
naryad №444), Rust 1.98.1, worktree + переиспользование target-кэша сборки
0.22 (полная компиляция 1м49с; prebuilt-ассетов в Releases нет).
0.23.0 = волны 11–13: офисный waker в публичном репо (№435), аудио-консент
(№428), origin-stamp'ы сессий (№430), recall-фронтдор памяти (№442),
timeseries-домен `SeriesHandle`/`ForecastHandle` (№440), registry 494→499 —
**все изменения аддитивные**, ломающих язык-поверхностей офиса в CHANGELOG
не заявлено.

## Решение

**`bin/mlog` = 0.23.0.** Guard-цепочка entrypoint сохранена без изменений
механики: кандидат = `bin/mlog`, бут-фолбэк = `bin/mlog-020` (0.20.0 —
последний бинарь, грузящий сырой app.mlog: lax-аудит + корректный
try-контракт). **`bin/mlog-022` вендорен как прошлый-хороший/тест-гвард**
(роль mlog-021 из ADR-0005 переходит к нему); `bin/mlog-021` выведен из
репо (восстанавливается из git-истории при необходимости), 0.19 вне
ротации.

## Что проверено (полная методология ADR-0005, блоки B.2–B.5)

1. **Статика `check app.mlog`:** вывод 745 строк — **байт-идентичен**
   0.22↔0.23 (0 parse error; хвост onX/csrf-предупреждений тот же).
2. **Статика `audit`:** raw (606 строк) и с мостом №421
   (`profile legacy { egress: permissive_with_audit }`) — выводы
   **байт-идентичны** 0.22↔0.23; те же 13 Category A долга №327 raw,
   с мостом — чисто. Гвард CI «долг не растёт» совместим: все
   `dept/*.mlog` (27 файлов) на 0.23 дают rc∈{0,2} без `[ERROR]`.
3. **Serve-стенд полного стека** (`scripts/serve_stack.sh`, git archive
   HEAD, METALOGOS_SERVE_BACKEND=interpreter, llm_proxy :4000 +
   serve :10001 + reverse_proxy :10000): бут `/health` ok прямо и через
   прокси; `/version`, webhook `/status`, `/osp/analyze` (ping —
   известный артефакт стенда «Forbidden», идентичен 0.21/0.22), webhook
   Эксперт, `/lz`, `/cron/control`, `/schedules/list` — **полный реестр
   7 слотов + keep-alive (Europe/Moscow), ответы идентичны 0.22**.
   Единственная дельта первого прогона (webhook Эксперт: 0.22 вернул
   `Handler error: parse_json()…`) — **разовый флейк холодного
   LLM-прокси на стороне 0.22**: прицельная проба ×3 на обоих бинарях
   (`scripts/probe_expert_webhook.sh`) дала `ok` 3/3 на каждой,
   `parse_json` в логах — 0.
4. **try-контракт (B.5):** матрица 11 фикстур (`mlog run`,
   `scripts/tryrun_all.sh` в конфигурации 022-vs-023): **0.23 ≡ 0.22
   на всех кейсах** — шовный путь TryVal (успех = значение, неудача =
   «()») и raw-путь (`to_string(try X)` прозрачен) без изменений.
5. **Пин бэкенда (B.1)** не требовал изменений: `METALOGOS_SERVE_BACKEND=
   interpreter` уже задан явно в entrypoint.sh и render.yaml (наследие
   №349); 0.23 его уважает (бут-лог: «backend: interpreter»).

## Что намеренно НЕ включено

- Новые возможности 0.23 (`recall`, timeseries/`series_*`, embodied
  хэндлы, audio-консент) — потребность не заявлена; отдельные наряды.
- Миграция долга №327 и снятие моста №421 — долг сохраняется, мост
  остаётся в бут-пути кандидата.
- Идиома `TryVal(try …)` (578 мест) не мигрирует на структурный try.

## Последствия

- Прод едет на 0.23 с прежней guard-пробой; откат: в entrypoint
  `MLOG_BIN=./bin/mlog-022` (прошлый-хороший) или `./bin/mlog-020`
  (аварийный).
- Гейт ① кутовера cron («native schedules OK» в бут-логе) теперь
  проверяется на буте 0.23; cron-job.org не трогается до двух зелёных
  гейтов (наследие кутовера).
- Бут-шум `[REDACT][audit-event]` (новый класс 0.22) сохраняется —
  безошибочный, задокументирован в ADR-0005.
- Рост бинаря: bin/ несёт 0.23 + 0.22 + 0.20 (~86 МБ) — приёмлемо;
  следующий переход может вывести 0.20, если VM/interpreter-гарантии
  0.23 подтвердятся soak'ом.
