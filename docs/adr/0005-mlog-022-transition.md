# ADR-0005: Переход боевого бинаря Metalogos с 0.19.0 на 0.22.0

**Статус:** принято (наряд #349, P1 infra, 2026-09-24)
**Дата:** 2026-09-24
**Контекст решения:** наряд #349 (источник — владелец); триггер — наряд №421
употребил синтаксис `profile legacy {...}` (0.20+), сломавший бут на 0.19.0
(хотфикс PR #333); мост ADR-0161 оставался заблокированным до реального
перехода. Сборка — из тега `v0.22.0` (ShkodnikAI/Metalogos-, main 04b2803),
Rust 1.98.1 через rustup (сеть песочницы rustup не блокирует — препятствие
A.1 наряда не реализовалось; prebuilt-ассетов в Releases нет).

## Решение

**`bin/mlog` = 0.22.0.** Фолбэк guard-пробы entrypoint — `bin/mlog-020`
(0.20.0). `bin/mlog-021` остаётся вендоренным (тест-гвард), но из бут-пути
выведен. 0.19.0 выведен из ротации (остаётся в git-истории и в
`metalogos-upstream`).

### Почему фолбэк именно 0.20, а не 0.21/0.19

- **0.21 не может быть фолбэком**: его бут-аудит на **сыром** app.mlog
  красный (Category A), а ветка фолбэка entrypoint подаёт именно сырой
  файл (мост №421 добавляется только в аугментированную копию кандидата).
- **0.19 деградировал ещё до наряда**: шов `TryVal(x) = x.value`
  (dept/utils.mlog:415, №422) на 0.19 падает на каждом выполняющемся сайте
  («cannot access field 'value' on non-struct value») — сырой `try` в 0.19
  прозрачен (успех = голое значение), шов рассчитан на TryResult-структуру
  0.20+. «Безопасный фолбэк 0.19» таковым не был с №422: /health живёт,
  но все TryVal-флоу (LLM/HTTP/DB-обращения) на 0.19-пути ошибочны — это
  согласуется с инцидентом #333 («битые /health /version»).
- **0.20** — последний бинарь, который (а) грузит сырой app.mlog
  (lax-аудит эпохи до №327-цензов) и (б) исполняет офисный шов TryVal
  корректно (TryResult-эра).

## Что проверено (Блок B наряда #349)

1. **Статика (`check`, `audit`) на актуальном app.mlog main 61ed9b6:**
   0 parse error у обеих версий; состав «undefined: function …»-ошибок
   чекера идентичен 441↔452 с двумя отличиями в пользу 0.22 (чекер 0.22
   знает грант-билтины `grant_issue`/`db_execute_with_grant` №391); хвост
   предупреждений (csrf/onX) идентичен. Аудит 0.22 raw — 13 Category A
   (те же классы долга №327, что у 0.21: private-db `InitDB`×3 +
   egress×10); с мостом №421 — 0 ошибок / 20 предупреждений, множество
   предупреждений идентично 0.19.
2. **`serve` реального app.mlog (аугментированного по №427) + полный стек**
   (llm_proxy :4000, reverse_proxy :10000, sqlite): `/health` → 200
   «ok» напрямую и через reverse-прокси; `/version` → ok; webhook
   `/status` → ok; `/lz`, `/cron/control` → ok; `/schedules/list` →
   полный реестр 7 слотов + keep-alive (Europe/Moscow). Ответы всего
   suite **байт-идентичны** прогону того же стенда на 0.21.
3. **try-контракт (B.5):** в кодовой базе 578 мест `TryVal(try …)` и
   395 проверок `to_string(x) == "()"`. Матрица 11 фикстур
   (`mlog run`, чистая семантика): **0.22 ≡ 0.21** на всех кейсах шовного
   пути (успех = значение, неудача = «()»); **0.22 ≡ 0.19** на raw-кейсах
   (`to_string(try X)` прозрачен — upstream восстановил контракт 0.19,
   issue #602 апстрима; на 0.21 raw рендерил TryResult-структуру).
   Репродукции: `scripts/gen_tryfixtures.py`, `scripts/tryrun_all.sh`,
   `scripts/serve_stack.sh`; пробы — `n349-results/`.
4. **pytest:** полный suite на дереве с 0.22 — 854 passed / 0 failed
   (один флака test_activity_feed при прогоне сразу после установки
   пакетов — воспроизведения нет, на чистом main тоже 854 passed).
5. **Явный пин бэкенда (B.1):** `METALOGOS_SERVE_BACKEND=interpreter`
   — теперь задан явно и в entrypoint.sh, и в render.yaml (стейджинг).
   Живая демонстрация риска дефолта: serve без пина молча садится на VM
   (ADR-0171) — в пробе 0.21/0.22 VM-путь возвращал пустые 200.

## Что намеренно НЕ включено

- Новые возможности 0.20–0.22 (`profile duty`, typed `Memory<K>`,
  session-модель, структурный try-контракт) — отдельные наряды.
- Миграция долга №327 (аудит-ценз диалогового контура) — поэтому мост
  №421 остаётся в бут-пути кандидата.
- `METALOGOS_SERVE_BACKEND=vm` — блокирован находкой №419 (VM-хендлеры
  не видят db_decl), не является частью перехода.
- Идиома `TryVal(try …)` не заменяется на структурный try 0.22 — 578
  мест работают как есть; снятие шва — отдельный наряд после №327.

## Последствия

- Мост ADR-0161 разблокирован: прод едет на 0.22 с той же guard-пробой.
- Нативные расписания (№419-бутстрап) исполняются на 0.22 — контракт
  cron_add/TZ 0.21+ сохранён (реестр читается, классы ответов идентичны).
- Гейт кутовера ① («native schedules OK» в бут-логе) теперь проверяется
  на буте 0.22; cron-job.org не трогается до двух зелёных гейтов.
- Рост шума бут-логов: 0.22 пишет `[REDACT][audit-event]`-строки при
  check/audit — класс вывода новый, безошибочный, задокументирован.
