# ADR-0013: Один источник правды по тексту промпта отдела — departments/<dept>.md ссылается на library/<dept>.md (наряд #447)

**Статус:** принято (исполнительская часть наряда #447 [P1][ARCH], волна «аудит 2026-09-30»).
**Дата:** 2026-10-01
**Контекст решения:** наряд #447 A.2 — «Один источник: либо `departments/*.md` содержит только машинную декларацию (модель, инструменты, лимиты) и ссылается на `library/*.md` за текстом, либо слить».

## Контекст

До ADR текст отдела существовал в двух местах с разным содержанием (факт аудита: все 8 сравненных пар различаются):

| Файл | Кто читает | Что несёт |
|---|---|---|
| `departments/<dept>.md` | Python: `proxy/departments.py` (FO-018) → `proxy/core.py` `get_dept_prompt` (высший приоритет, «последний wins»); `permission` → Guardian-оверлей | frontmatter (model/temperature/tools/permission/mode) + 1-абзацный системный промпт (verbatim `CONDENSED_PROMPTS`, миграция 1-в-1 закреплена тестом) |
| `library/<dept>.md` | mlog-контур: `app.mlog` `read_file("library/<dept>.md")` (команды `/quarterly-review`, LZ/OSP/legal/marketing-команды, линии 3187/4274–4355) | развёрнутый профиль отдела: функция, психотип, компетенция, жёсткие правила (41–129 строк) |

Файлы решали РАЗНЫЕ задачи (компактный промпт Python-плоскости vs глубокий профиль mlog-контекста), но ни контракт, ни гвард этого не фиксировали — расхождение выглядело как дрейф и не было охраняемым.

## Решение

Принят вариант «ссылка» из наряда:

1. **`departments/<dept>.md` — только машинная декларация.** Тело файла — одна директива `@include:library/<dept>.md`. Frontmatter без изменений (model/temperature/tools/permission/mode).
2. **`library/<dept>.md` — единственный носитель текста.** В конец профиля добавлена секция `## Системный промпт` с текстом, перенесённым **байт-в-байт** из тела декларации (нулевое изменение поведения: `prompt_for(dept)` возвращает тот же `CONDENSED_PROMPTS`-текст — гвард `test_prompts_are_verbatim_condensed` продолжает проходить).
3. **Механика резолва** (`proxy/departments.py`): `_resolve_prompt()` — тело-директива резолвится в секцию `## Системный промпт` целевого файла; путь только внутри корня офиса (запрет `..` и абсолютных); файл/секция не найдены → `DepartmentsConfigError` (громкая ошибка, старт роняется — стиль FO-018). Тело без директивы работает как раньше (обратно совместимо с юнит-тестами на tmp-декларации). Секция прекращается на следующем `##` или маркере `**End of profile …**`. Кэш деклараций инвалидируется и по mtime `library/*.md` тоже.

## Альтернативы

- **Слить файлы** (перенести frontmatter в library/*.md): mlog-читатели (`read_file` + `redact` в app.mlog) получат frontmatter в текст профиля — миграция ~десятка сайтов чтения в mlog-контуре, выше риск; отклонено.
- **Зафиксировать расхождение как осознанное** (два артефакта, гвард-сверка полей): не устраняет двойной источник, а легализует его; против буквы наряда; отклонено.
- **Включить в промпт Python-плоскости полный профиль** (41–129 строк): значительный токен-дрейф каждого запроса; отклонено.

## Последствия

- Текст промпта отдела редактируется в ОДНОМ месте — `library/<dept>.md`; расхождение «два текста одного отдела» структурно невозможно (декларация текст не содержит).
- Гвард-тест `tests/test_n447_single_source.py`: дублирующий текст в теле декларации (кроме директивы) для реальных 14 департаментов → падение; цель директивы и секция обязаны существовать; `prompt_for` обязан совпадать с `CONDENSED_PROMPTS` 1-в-1.
- Риск не изменён: изменение текста секции меняет поведение Python-плоскости всех запросов отдела — редактировать осознанно (как и раньше через departments, но теперь с полным контекстом профиля перед глазами).
- mlog-контур не затронут: он читает файлы library целиком (redact), секция `## Системный промпт` в тексте профиля безвредна для промптов mlog-команд.
