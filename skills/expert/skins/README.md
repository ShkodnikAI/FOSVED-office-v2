# Шкурки Эксперта (EXP-1, решение владельца 20.11)

«Шкурка» — доменная база знаний, которую Эксперт **надевает по запросу**: тот же `/expert`, та же глубина, другой домен. Отдельных подкоманд доменов нет.

## Формат

Каждая шкурка — один файл: `skills/expert/skins/<домен>/SKIN.md`. Структура:

```markdown
---
domain: <ключ домена, латиницей, == имени каталога>
professions: [<профессия и узкая специализация 1>, <профессия 2>, …]
triggers: [<ключевые слова запроса, по которым шкурка надевается>, …]
standards: [<нормы отрасли / ГОСТ / ISO / регламенты — только реально известные и проверяемые>]
sources: [<специализированные сайты/базы для живого поиска>, …]
tools: [<функции EXP-2, доступные шкурке: avby_listings | residual_value | operation_cost | chart>, …]
---

## Failure catalog — типовые отказы и как их скрывают

- **Что:** … **Механизм:** … **Как скрывают:** … **Серьёзность:** низко/средне/критично
  (пометка «опыт практиков, документально не подтверждено» — если нет источника)

## Domain data — доменные данные для цифр

(таблицы/числовые ориентиры, перенесённые или накопленные при разборах;
каждая цифра — с источником или пометкой «оценка/опыт практиков»)
```

## Правила

1. `domain` обязан совпадать с именем каталога; все поля фронтматтера обязательны и непусты (валидатор EXP-2 отклоняет шкурку).
2. `tools` — только реально существующие функции EXP-2: `avby_listings`, `residual_value`, `operation_cost`, `chart` (общие для всех шкурок: живой поиск Tavily).
3. `standards` — без выдуманных номеров: перечислять только проверяемые нормы/регламенты.
4. Пункт без механизма («почему так») и без источника/пометки «опыт практиков» — брак.
5. Содержимое шкурок **не пишется заранее**: шкурка появляется/пополается по мере реальных разборов. Исключение — `auto` (перенесена из кода, EXP-1).

## Каталог шкурок

- `auto/` — автомобили: российский рынок, остаточная стоимость, TCO, красные флаги (EXP-1, перенесена из `ExpertAutomotiveKB`/`ExpertAutomotiveSkillSet`).
